# World Liquor 0.1.173

Beheading parity with Java `EventHandlers` (NeoForge 1.21.1 author 1.1.11 / CF9066406; the beheading handlers are unchanged in 1.1.12).

Java: `onLivingIncomingDamage` requires a direct `LivingEntity` attacker with the effect, a living target outside the `kaleidoscope_world_liquor:bosses` tag and `RANDOM.nextDouble() < 0.04 + amplifier * 0.03`; it writes `BEHEADED_MARKER` and `BEHEADING_PROCESSING` into the target's persistent data, cancels the incoming damage and hurts the target for 10000 with a `playerAttack` / `mobAttack` source attributed to the attacker. If the health did not drop (blocked) it sets 1, hurts 2 and, if still alive, sets 0 and dies. `onLivingDropsBeheading` adds the head to a marked entity's drop list unless an identical head (`isSameItemSameComponents`) is already there, then clears the marker.

`runtime/BP/scripts/beheading.js` now owns this flow. The marker is the target's dynamic property `kaleidoscope_world_liquor:beheaded`, so a target saved by a totem or the world being saved still drops its head on the next death, as in Java. The direct hit keeps the attacker-attributed 10000 damage on the same before-event; one tick later a target whose health did not fall receives the Java fallback (set 1, 2 damage from the attacker, set 0), while `BEHEADING_PROCESSING` suppresses another roll during that inner hurt. On death the head is resolved (vanilla class heads, registry heads, player head) and deduplicated against the native `entityItemDrop` list; an entity that produces no drop list gets the head two ticks after death. A player head carries `<name>'s Head` and `SkullOwner: <name>` as name and lore because Bedrock scripts cannot set a skull owner skin. Failures are recorded in `beheadingDiagnostics`, never retried.

`tests/beheading.test.mjs` covers the chance expression and bosses tag, boss/dead/failed-roll hits, the marker and single fallback schedule, the blocked fallback sequence, re-entry suppression, deduplication including renamed heads, the no-drop-list timeout, player and registry heads, marker persistence across a fresh install and a rejected spawn. The existing registered-callback case in `tests/combat-source.test.mjs` still pins the 10000 direct hit, the direct-LivingEntity requirement and the bosses exclusion.

Not equivalent and still open: Bedrock cannot cancel the incoming event and start a second `playerAttack` / `mobAttack` hurt, so armour, enchantment and knockback effects of the original hit apply once to the 10000 instead of to a fresh source; the player head has no skin; totem, armour and Tequila concurrency and the real native drop-list order remain acceptance scenarios. Client acceptance stays pending and `production_ready=false`.
